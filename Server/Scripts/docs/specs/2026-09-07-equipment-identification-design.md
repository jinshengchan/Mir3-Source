# 装备鉴定脚本修正设计

## 目标

恢复隐藏 NPC 215“鉴定稀世装备”和 NPC 216“兑换鉴定石”的实际功能，替换当前错误绑定的钓鱼商逻辑。只修改 `D:\Debug\4月18日更新\Server\Scripts`，不改数据库、C#、`Scripts888`，不部署或重启。

## 已确认的数据契约

- 所有目标物品均以“未鉴定”开头；去掉该前缀后，可在当前 `System.db` 中唯一匹配同名稀世成品。
- 未鉴定物品的 `RequiredAmount` 为 1 至 5，对应“鉴定石一级”至“鉴定石五级”。
- NPC 215、216 位于隐藏 GM 地图且 `Display=False`，因此通过现有“管理中心”调用，不修改实体地图。

## 设计

1. 新增 `Npc\鉴定稀世装备.py`，监听 NPC 215。
   - 玩家放入一件背包中的未鉴定装备。
   - 脚本再次核对物品名称、等级、同名成品和对应鉴定石。
   - 每次消耗一件未鉴定装备和一颗同等级鉴定石，100% 生成一件对应成品。
   - 产物先用 `ItemCheck`、`CanGainItems`、`SEnvir.CreateFreshItem` 和 `GainItem` 校验并发放；成品保留源物品的 `Bound`、`Worthless` 标记。
   - 保留原物品的绑定和不可出售标记；发放失败时不扣材料。
2. 新增 `Npc\兑换鉴定石.py`，监听 NPC 216。
   - 直接购买五档鉴定石，成本固定为：一级 `高级碎片 x1 + 元宝 x50`、二级 `x2 + x100`、三级 `x3 + x150`、四级 `x4 + x200`、五级 `x5 + x250`。
   - 直接购买使用现有 `GiveItems` 的成功返回值；成功发放后才扣除元宝和高级碎片。
   - 只允许向下分解：五级到四级、四级到三级、三级到二级、二级到一级。
   - 比例为 1:1，防止材料数量膨胀。
   - 发放低一级鉴定石成功后才扣除高一级鉴定石。
3. 在 `Npc\管理中心.py` 增加菜单 38“装备鉴定”和菜单 39“鉴定石分解”，分别调用 NPC 215、216。
4. 在 `Npc\__init__.py` 导入两个新模块；在 `Npc\潘夜岛\__init__.py` 停止导入错误占用 215、216 的两个钓鱼商脚本。保留原脚本文件，不删除。

## 错误处理

- 非未鉴定装备、等级超出 1 至 5、找不到唯一成品、缺少同级鉴定石或背包无法接收产物时，显示明确提示且不扣除任何物品。
- 每次确认操作时重新读取背包，避免重复点击使用过期状态。

## 验证标准

- Python 语法编译通过，主入口导入无重复监听 215/216。
- 数据库中全部未鉴定物品均能按规则映射到唯一成品，且等级都在 1 至 5。
- 静态契约验证两个管理中心入口、两个监听器、扣除顺序及失败不扣材料。
- 不宣称完成在线热加载或游戏内验收；这些需要后续脚本重载或服务器重启后实测。
