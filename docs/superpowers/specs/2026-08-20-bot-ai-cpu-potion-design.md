# 假人 AI CPU 与喝药扫描优化设计

## 目标

降低新版刺客技能链启用后，低蓝状态造成的重复喝药调用、背包扫描和短命分配，同时保持刺客会放技能、40级换图、紧急补血和现有调度语义不变。

## 已确认事实

- 主 AI 每 200ms 驱动一个稳定分片，每名假人约 800ms 执行一次完整行为。
- 独立喝药定时器每 200ms 投递喝药检查。
- 通用施法帮助在魔力不足时仍直接调用 `ProcessBotPotionMonitor`；刺客一轮可能依次尝试多个技能，从而在独立定时器之外重复进入喝药路径。
- 非紧急喝药成功后有冷却，但无药、无法使用或购买失败时没有等价的短退避，可能每 200ms 重扫背包。
- 当前旧版进程也约有 4.9GB Private Bytes；本次只减少 bot 热路径扫描和分配，不宣称修复整体内存泄漏。

## 行为设计

1. 通用战斗施法入口发现 `magic.Cost > player.CurrentMP` 时直接返回失败，不再同步调用普通喝药监控。独立 200ms 喝药定时器继续负责常规低蓝补给。
2. `ProcessBotPotionMonitor` 对非紧急检查使用 800ms 的失败/检查退避：通过现有 `_botPotionCooldownTime` 在进入昂贵背包扫描前预留下一次检查时间；实际成功喝药后仍以药品真实冷却覆盖该时间。
3. HP 不高于 `BotPotionEmergencyHpPct`（15%）时继续绕过退避，维持紧急追喝。
4. 不改变 `forceFullRecovery` 的补满目标，只让非紧急补满检查遵守同一800ms扫描退避。
5. 不修改地图评估、换图阈值、职业技能优先级、药品选择评分、购买数量、金币扶持或200ms定时器周期。

## 文件边界

- `Server/BotManager.Support.cs`：非紧急喝药扫描退避。
- `Server/BotManager.Combat.cs`：移除两个通用施法帮助中的同步普通喝药调用。
- `.diagnostics/bot-ai-cpu-potion-contract.ps1`：聚焦 RED/GREEN 契约。
- `CHANGELOG.md`：记录源码、验证与未完成的在线A/B验证。

不修改客户端、ServerLibrary、数据库、配置、部署目录或其他假人策略。

## 验证

- 新契约在生产修改前必须因缺少800ms退避及仍有通用施法同步喝药调用而 RED。
- 修改后新契约 GREEN；一期21项契约及40级/刺客6项契约继续 GREEN。
- `ServerLibrary` 与 `Server` 使用 Debug/AnyCPU 构建，服务端输出到隔离目录，不覆盖当前运行的旧版。
- 运行时仍需相同假人数量、职业比例和地图负载做旧版/新版至少5分钟 A/B；静态契约和构建不能证明 CPU 已下降。
