# 假人 AI Python 策略层设计

## 目标

在不运行或模拟 PC 客户端挂机主循环、不把高频寻路和战斗执行迁入 IronPython 的前提下，将假人的地图适配策略和四职业技能优先级改为可重载的 Python 策略，使调整等级路线、地图权重和技能顺序时不再重新编译 `Server.exe`。

## 已确认事实

- 服务端使用 IronPython 2.7.11；`SEnvir.LoadScripts` 创建并复用一个 Python 引擎和作用域。
- 假人主 AI 以 200ms 分片调度，每名假人约 800ms 执行一次完整行为；独立喝药监控每 200ms 运行。
- 地图适配正常每 60 秒评估一次，打金模式每 180 秒评估一次。
- PC 客户端挂机逻辑依赖 `GameScene`、客户端地图对象、`CEnvir` 和网络封包，不能由服务端假人直接调用。
- 服务端假人已经通过 `PlayerObject` 直接执行移动、攻击和施法，现有 `BotSkillSelector` 负责职业技能决策。

## 设计边界

### Python 负责

- 按等级、职业和资源状态划分地图策略阶段。
- 对 C# 提供的候选地图事实进行过滤、评分和排序。
- 决定驻图时间、切图分差和目标地图编号。
- 定义战士、法师、道士和刺客的技能优先级表。
- 按等级段、血量段、蓝量段、目标距离、附近怪物数量及组队状态选择技能优先级配置。

### C# 负责

- 从当前服务端对象生成只读数据快照，不把活动中的地图、怪物或数据库集合交给 Python 遍历。
- 对候选地图执行不可绕过的安全校验，包括地图存在性、进入限制、危险度、组队跟随、攻城状态和落点有效性。
- 缓存已验证的四职业技能优先级；战斗 Tick 只读取 C# 缓存，不调用 Python。
- 校验技能已经学习、等级满足、冷却完成、蓝量足够且符、毒等消耗品可用。
- 继续执行现有选怪、寻路、移动、攻击、施法、喝药、补给和传送逻辑。

## 组件与数据流

### 脚本文件

新增一个权威脚本 `Server/Scripts/BotAI.py`，使用 Python 2.7 兼容语法。`Server.csproj` 将其作为内容文件复制到构建输出的 `Scripts` 目录；源码构建不自动覆盖当前运行目录。

脚本只暴露两个稳定入口：

- `select_map(request)`：接收一次地图策略请求并写入目标地图编号和原因。
- `get_skill_priorities()`：返回四职业技能优先级配置快照。

### 地图策略请求

C# 在现有 60/180 秒地图评估点创建一次请求。请求只包含值类型或简单数据对象，例如人物等级、职业、当前地图、金币状态，以及候选地图的编号、名称、最低等级、怪物平均等级、怪物数量、经验/掉落/金币倍率、技能书匹配信息和 C# 计算的硬安全指标。

Python 完成全部可调地图策略并返回一个候选地图编号。C# 不再维护另一套可调评分权重，但保留硬安全校验。目标编号不属于本次候选快照、地图已失效或没有合法落点时，本轮不切图。

### 技能优先级缓存

服务端加载或重载 `BotAI.py` 时读取一次 `get_skill_priorities()`。C# 将结果转换成经过验证的只读缓存，职业战斗方法继续调用 `BotSkillSelector`，但选择顺序来自缓存。

脚本不会在每个战斗 Tick、每次攻击或每次技能尝试时运行。调整脚本后，只有成功解析且所有引用的职业、技能和条件都合法时才原子替换缓存。

## 失败处理

- 脚本文件缺失、语法错误、入口缺失或执行异常时记录一次明确日志，不能让异常逃入假人主循环。
- 地图策略调用失败或返回非法地图时，假人留在当前地图，本轮不切图，战斗继续。
- 新技能配置无效时保留上一份有效缓存；服务端首次启动且没有有效缓存时使用当前 C# 默认技能顺序。
- 单个假人的地图请求失败不能影响其他假人。
- 日志需要限频，禁止每 200ms 重复输出同一脚本错误。

## 性能要求

- 地图脚本调用保持现有 60/180 秒节奏，不新增战斗热路径调用。
- Python 引擎、脚本作用域、入口函数和技能配置必须复用或缓存，禁止每次请求重新创建引擎、编译脚本或导入模块。
- Python 不直接遍历 `SEnvir.Maps`、刷新点、掉落数据库或活动中的 `MapObject` 集合。
- 本设计优化的是维护和热调整效率，不宣称降低 CPU 或内存；运行时性能必须与旧版 `Server.exe` 做同假人数 A/B 验证。

## 第一阶段实施范围

第一阶段只建立一个策略桥，并接入：

1. 完整地图适配策略；
2. 四职业技能优先级的加载和 C# 缓存。

不迁移选怪、寻路、攻击、施法、喝药、补给、组队、PK、攻城或客户端挂机代码。不得删除现有 C# 默认技能顺序，因为它是首次加载失败时的安全回退。

## 预计文件边界

- `Server/BotManager.Combat.cs`：在现有地图评估点调用脚本策略，并保持最终安全校验和传送。
- `Server/BotManager.Support.cs`：脚本加载、请求数据对象、技能配置验证、缓存和限频错误状态。
- `Server/BotSkillSelector.cs`：从已验证缓存读取职业技能优先级，保留当前默认顺序。
- `Server/Scripts/BotAI.py`：唯一可调地图策略和四职业技能优先级。
- `Server/Server.csproj`：将 `BotAI.py` 复制到构建输出的 `Scripts` 目录。
- `.diagnostics/bot-ai-python-strategy-contract.ps1`：聚焦 RED/GREEN 契约。
- `CHANGELOG.md`：记录实现范围、验证结果和未完成的在线 A/B 验证。

不修改客户端、数据库、服务端配置、现有运行目录或其他脚本。

## 验证要求

1. 先新增契约并在生产修改前得到 RED。
2. 契约必须证明地图脚本只出现在 60/180 秒评估路径，不出现在 200ms 喝药或职业战斗 Tick。
3. 契约必须证明技能配置只在加载/重载时解析，战斗路径只读取 C# 缓存。
4. 使用 Python 2.7 对 `BotAI.py` 做语法检查，并覆盖四职业、非法技能、非法地图、脚本异常和保留旧缓存场景。
5. 运行现有假人一期、40级/刺客、CPU/喝药、刺客定位、道士技能与道士补给契约。
6. 使用 Debug/AnyCPU 将 `ServerLibrary` 与 `Server` 重建到隔离目录，要求 0 错误；不覆盖当前旧版服务端。
7. 实际上线前，以相同假人数、职业比例和地图负载分别运行旧版和新版至少 10 分钟，比较 CPU、Private Bytes、脚本异常数、技能释放和地图切换结果。

## 不在本设计内

- 不直接调用或嵌入 `Mir3.exe` 的客户端挂机主循环。
- 不为每个假人创建客户端场景、网络连接或 Python 引擎。
- 不实现自动热监视文件；第一阶段只复用服务端现有脚本加载/重载动作。
- 不承诺脚本化本身降低 CPU 或内存。
- 不部署、不启动或停止当前服务端。
