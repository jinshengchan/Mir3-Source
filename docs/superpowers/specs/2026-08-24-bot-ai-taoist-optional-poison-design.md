# 假人道士可选施毒与连续输出设计

## 目标

修复道士施毒后偶尔长时间不释放攻击技能、站在原地无动作的问题。施毒不再是进入攻击流程前必须完成的步骤；灵魂火符、月魂断玉、月魂灵波始终优先。

## 已确认行为

1. 道士每个战斗帧先按以下固定顺序尝试攻击技能：
   - `MagicType.ExplosiveTalisman`（灵魂火符）
   - `MagicType.EvilSlayer`（月魂断玉）
   - `MagicType.GreaterEvilSlayer`（月魂灵波）
2. “尝试”以实际施法成功为准。第一招虽通过就绪检查但因施法前置条件失败时，继续尝试后续攻击技能，避免第一招长期堵住整个技能链。
3. 只有三种攻击技能均未成功施放时，才允许把施毒作为补空档技能；目标已经具备对应毒状态、毒技能未就绪或药粉不可用时直接跳过施毒。
4. 上次施毒记录仅可保留为统计信息，不再阻止攻击技能选择，也不再要求“施毒后必须成功打一符”才能解除状态。
5. 道士和法师身边一格内有可攻击怪物时仍优先拉开距离；成功移动的当前帧不施法。
6. 十级以上道士、法师仍不使用普通攻击。所有技能均不可用且已处于合适距离时允许短暂等待下一战斗帧，不新增高频轮询。

## 实现边界

只修改：

- `Server/BotSkillSelector.cs`
- `Server/BotManager.Combat.cs`
- `.diagnostics/bot-ai-taoist-wizard-combat-priority-contract.ps1`

不修改寻路、喝药、补给购买、自动学习、法师技能优先级、刺客逻辑、数据库和部署目录。不增加配置项、计时器、线程、缓存或持久化状态。

## 数据流

`ProcessBotTaoistCombatAction` 先处理贴身撤退，然后获取按固定顺序排列的已就绪攻击技能候选。逐个调用现有远程施法链，任一技能成功施放或成功执行拉距后立即结束当前帧。全部攻击候选均未成功后，再获取当前目标需要的可选施毒技能并尝试一次。仍未成功则进入现有远程无技能兜底。

## 验证标准

专项契约必须先出现 RED，再在生产修改后达到 GREEN，并证明：

- 三种攻击技能实际尝试顺序准确且没有其他攻击技能混入。
- 攻击技能尝试发生在任何施毒选择之前。
- 上次施毒记录不再构成攻击门闩。
- 第一种攻击技能实际施法失败时能继续尝试后两种。
- 施毒只在全部攻击技能未成功后尝试一次。
- 贴身撤退、十级分界、自动装备护身符和法师既有行为保持不变。

随后运行现有 Phase1、40级/刺客、CPU/喝药相关契约，并执行 `Debug / AnyCPU` 独立重建。构建产物不自动部署；游戏内连续战斗观察仍是最终运行验收缺口。
