# PatchManager 上传诊断设计

日期：2026-09-01

## 目标

为端游、手游普通补丁和手游 APK 的共用 FTP 上传链路增加可定位的错误提示与本地日志。上传失败时不得继续显示成功进度、删除待上传临时文件或抛出未处理异常。

## 已确认问题

- `UploadFileCompleted` 当前只结束等待，不检查 `e.Error` 或 `e.Cancelled`，失败也可能被计为成功。
- 普通补丁上传失败时仍会删除本地临时 `.gz` 文件。
- `SaveVersion` 上传 `PList.Bin` 或 `APKVersion.bin` 时没有异常边界，失败会弹出系统未处理异常窗口。
- 端游、手游普通补丁和手游 APK 共用 `Upload`、`UploadPatch`、`SaveVersion`，应在共用链路修复，不能复制三套逻辑。

## 设计

### FTP 连接测试

- 端游区域增加“测试端游 FTP”按钮，手游区域增加“测试手游 FTP”按钮；两套地址、登录开关和账号独立取值。
- 测试在后台任务中运行，期间禁用对应测试按钮，不能阻塞界面。
- 每次测试在 FTP 根目录使用不可预测且不重复的临时文件名，例如 `.patchmanager-test-{Guid}.tmp`，不得覆盖现有文件。
- 临时文件写入少量随机标记内容，随后回读并逐字节比对，确认登录、被动/主动数据通道、上传、服务器落盘和下载均有效。
- 校验成功后删除远端临时文件。只有上传、回读校验和删除全部成功时才提示“连接及读写测试成功”。
- 任一阶段失败都显示具体阶段、FTP/Web 状态和日志路径。若读写成功但删除失败，必须明确提示远端残留文件名，不能误报完整成功。
- `PatchManager.log` 记录连接测试开始、上传完成、回读校验、删除完成和最终结果；记录目标但不记录密码。
- 测试不得读取、覆盖或删除 `PList.Bin`、`APKVersion.bin` 和正式补丁文件。

### 上传结果

- 上传完成回调必须读取 `e.Error` 与 `e.Cancelled`。
- 只有服务器端操作无错误且未取消时，才累计完成进度并删除普通补丁的本地临时文件。
- 上传失败后设置现有 `Error` 状态、停止当前队列，并恢复界面操作状态。
- `SaveVersion` 改为返回成功或失败；调用方根据结果阻止后续发布步骤。

### 错误提示

错误弹窗使用中文短摘要，至少包含：

- 模式：端游、手游普通补丁或手游 APK；
- 阶段：上传补丁文件、上传 `PList.Bin` 或上传 `APKVersion.bin`；
- 目标文件或 FTP URI；
- 异常类型与简要原因；
- `WebExceptionStatus`；
- 如响应为 `FtpWebResponse`，显示 FTP 状态码与状态说明；
- 日志文件的完整路径。

状态栏显示同一错误的短摘要，不显示完整堆栈。

### 日志

- 文件固定为程序启动目录下的 `PatchManager.log`，失败时追加写入 UTF-8 文本。
- 每条记录包含时间、模式、阶段、目标、异常类型、消息、Web/FTP 状态、内部异常链和完整堆栈。
- 不记录 FTP 密码；不把 `NetworkCredential` 或配置对象序列化到日志。
- 日志写入本身失败时，原始上传错误仍必须正常弹出；弹窗附带“日志写入失败”的简短说明，不能再次形成未处理异常。

## 实现边界

允许修改：

- `PatchManager/PMain.cs`
- `PatchManager/PMain.Designer.cs`（仅增加两个测试按钮及事件绑定）
- `PatchManager/PatchManager.csproj`（仅在加入一个小型诊断辅助类时）
- 一个专用于格式化和追加日志的 `PatchManager` 辅助类（仅在测试隔离确有需要时）
- 一个针对本次行为的 PowerShell 契约测试

禁止修改：

- FTP 主机、端口、账号、密码和服务器配置；
- 补丁文件格式、`PList.Bin`/`APKVersion.bin` 协议；
- 客户端、服务端、手游工程的其他源码；
- 现有发布目录中的可执行文件，验证构建必须输出到隔离目录。

## 测试与验证

先建立 RED，再写生产代码：

1. 当前源码必须因“完成回调未处理错误”和“版本清单异常未捕获”而失败。
2. GREEN 后验证上传错误不会返回成功、不会删除临时补丁、会生成包含阶段和状态的诊断文本。
3. 验证日志文本不包含密码字段或实际密码。
4. 验证 `SaveVersion` 失败被转换为受控失败，不再越过 `CreatePatch` 成为未处理异常。
5. 验证端游和手游测试按钮使用各自配置；临时测试文件名唯一，执行顺序为上传、回读校验、删除，删除失败必须报告残留文件名。
6. 自动化测试不连接真实 FTP；真实服务器读写测试由用户运行新按钮完成，并作为运行验收单独记录。
7. 在隔离输出目录构建 `PatchManager.csproj`，不得覆盖桌面或工具目录中的现有 `PatchManager.exe`。

## 验收标准

- 端游与手游全部经过同一套错误处理和日志逻辑。
- FTP 上传失败时弹窗能指出具体阶段、目标和 FTP/Web 状态。
- `PatchManager.log` 包含完整异常证据且不包含密码。
- 失败不再显示为成功，不再删除尚未成功上传的临时文件。
- `PList.Bin`/`APKVersion.bin` 上传失败不再出现系统未处理异常窗口。
- 端游与手游各有独立 FTP 测试按钮；成功结论覆盖上传、回读比对和临时文件删除。
- 契约测试通过，隔离构建成功；真实 FTP、服务器落盘和线上发布仍作为未执行的运行验收单独说明。
