# 雪原活动副本单人进入设计

## 状态

已获用户确认，目标是让雪原荒村副本支持单人进入，同时保持现有组队规则。

## 范围与现状

只修改：

`D:\Debug\4月18日更新\Server\Scripts\Npc\雪原活动管理员.py`

雪原荒村副本使用 `Menu == 1`。现有逻辑要求 `Sender.GroupMembers` 为真，否则返回“没有队伍”，因此无队伍玩家无法进入。组队路径还会要求队长发起，并逐个检查队员的进入次数、等级、元宝和魔晶石。

当前人数判断是 `len(Sender.GroupMembers) < 0`。该判断实际上不会成立，但本次需求只增加单人入口，不修正这个已有行为，也不修改提示文字。

同名的 `Scripts888` 文件内容相同，但不在本次修改范围内。

## 目标

- 无队伍玩家可以作为单人进入雪原荒村副本。
- 单人仍需满足现有时间、等级、每日次数、100元宝和2个魔晶石条件。
- 单人成功进入时仍创建1530副本、设置副本变量、扣除费用和材料，并传送玩家。
- 有队伍时继续要求队长发起，并保留现有逐队员检查和处理规则。

## 非目标

- 不修改客户端菜单或显示文本。
- 不修改 `Scripts888`。
- 不修改其他菜单（包括其他副本入口）。
- 不把组队人数判断从 `< 0` 改成 `< 5`。
- 不改变副本地图、怪物、持续时间、费用、材料或变量名。

## 设计

在 `Menu == 1` 的现有时间、队长材料和个人次数检查之后，建立一次进入玩家集合：

- 有队伍时使用原来的 `Sender.GroupMembers`。
- 无队伍时使用只包含 `Sender` 的集合 `[Sender]`。

队长判断只对有队伍的情况生效；无队伍时直接进入原有的准入检查。准入检查统一遍历上述集合，因此单人复用现有的等级、次数、元宝和魔晶石检查。副本创建、变量设置、扣费和传送也统一遍历上述集合，保证单人与组队使用同一套进入结果。

保留现有队伍非队长的“不是队长”提示。无队伍不再返回“没有队伍”；如果单人不满足条件，沿用现有校验提示，不额外引入文案变更。

## 验证标准

### 静态验证

新增聚焦的 PowerShell 合同检查，确认目标文件：

1. `Menu == 1` 仍存在。
2. 单人集合 `[Sender]` 存在，并用于校验、扣费和传送遍历。
3. 有队伍时仍保留队长判断和原有准入条件。
4. 副本地图1530、100元宝、2个魔晶石和传送坐标未被改动。
5. `Scripts888` 不在修改范围内。

### 运行时验收

静态合同通过只能证明脚本文本满足设计，不能证明服务器已加载新文件。实际验收还需要把该文件复制到服务器实际加载的 `Server\Scripts` 目录并重启脚本宿主，然后分别测试：符合条件的单人、组队队长、组队非队长，以及条件不足的玩家。

## 回滚边界

代码实施前记录目标文件的原始 SHA-256；如果验证失败，只恢复该目标文件，不触碰其他脚本。
