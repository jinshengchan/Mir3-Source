设计草案，已确认传送费用和坐标，已确认执行范围，待生成执行计划。

## 范围与现状

只修改：

`D:\Debug\4月18日更新\Server\Scripts\Npc\其他\便捷传送.py`

地图资料和现有NPC传送逻辑显示 `奔马岛` 的地图编号为 `1551`，地图文件为 `20`，服务端地图文件为 `20.map`，现有可用坐标为 `(96,218)`。当前生效的便捷传送数据没有该地图菜单。现有的“危险地图传送：费用50000金币”分组使用菜单编号 `28` 和 `29`，因此新增菜单使用 `30`。当前脚本把主菜单文本复制在4个刷新路径中，新增按钮需要同步写入这4处，确保回收功能刷新后仍然显示。

## 目标

- 便捷传送主菜单的4个刷新路径均显示 `[奔马岛:30]`。
- 点击菜单 `30` 时，从金币中扣除 `50000`。
- 成功传送到地图 `1551` 的坐标 `(96,218)`。
- 保留现有传送函数、扣费逻辑和其他菜单行为不变。

## 非目标

- 不修改地图文件、地图数据库或客户端资源。
- 不修改桃源仙境相关 NPC、活动和地图限制逻辑。
- 不同步修改旧版便捷传送脚本。
- 不复制文件到服务器、不重启服务、不进行在线游戏验收。

## 设计

在 `TELEPORT_DATA["danger"]` 中新增：

```python
30: {"cost": 50000, "map": 1551, "x": 96, "y": 218}
```

在主菜单现有的 `50000金币` 危险地图分组中追加 `[奔马岛:30]`，并同步更新4个重复的主菜单文本。菜单分支会自动通过现有的 `handle_teleport` 读取该数据，执行金币检查、扣费和 `TeleportByMapIndex`，不新增重复传送逻辑。

## 验证标准

### 静态验证

使用聚焦的 PowerShell 检查确认：

1. 目标文件只出现一个菜单 `30` 的传送数据。
2. 菜单 `30` 的费用为 `50000`，地图为 `1551`，坐标为 `(96,218)`。
3. 主菜单4个刷新路径均包含 `[奔马岛:30]`，并位于50000金币分组。
4. 现有菜单 `28`、`29` 的数据未被改动。
5. `Scripts888` 和旧版 `Npc\便捷传送.py` 未发生变化。

### 运行时验收

静态检查只能证明脚本文本和目标范围正确，不能证明服务器已加载文件。实际验收需要将目标文件复制到服务器实际加载目录并重载脚本或重启服务，然后测试金币不足、金币足够和实际到达地图三种情况。本次不执行复制、重启或在线验收。
