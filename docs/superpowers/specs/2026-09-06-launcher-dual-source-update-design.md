# 登录器双下载源更新设计

日期：2026-09-06

## 目标

在不改变现有补丁格式和 FTP 发布流程的前提下，让 PC 登录器优先从对象存储或 CDN 的公开直链下载补丁；主下载源不可用时，自动切换到当前 HTTP 补丁服务器。玩家不需要选择线路或点击额外按钮。

## 已确认现状

- `LauncherWpf/MainWindow.xaml.cs` 当前只保存一个 `Host`，通过该地址下载 `PList.Bin` 和各个 `.gz` 补丁文件。
- `LauncherWpf/PatchInformation.cs` 的每条补丁记录包含相对文件名、压缩文件长度和原文件校验值；现有代码使用 MD5 比较本地文件。
- `LauncherSet/LMain.cs` 将一个更新地址写入生成登录器的尾部配置数据。
- `PatchManager` 通过 FTP 发布 `.gz` 文件和 `PList.Bin`，与登录器使用的 HTTP 下载地址相互独立。
- 三个相关工程均以 .NET Framework 4.8 为目标框架，可以继续使用 HTTP 或 HTTPS 公开直链。

## 方案选择

### 方案一：只改成对象存储单源

不修改登录器源码，直接把当前更新地址替换成对象存储根地址。实现最少，但对象存储不可用时没有备用线路，不满足已确认的容灾要求。

### 方案二：双地址自动切换

登录器配置包含主、备用两个 HTTP 根地址。登录器自动选择可用来源，不增加玩家操作。该方案改动集中在 `LauncherSet` 和 `LauncherWpf`，保留现有补丁协议和 FTP 流程。

### 方案三：界面按钮手动选线路

在登录器界面增加“网盘下载”和“服务器下载”按钮。除了下载逻辑，还需要调整 WPF 界面、按钮状态和用户操作流程，复杂度更高，并可能让玩家选到不可用线路。

采用方案二。

## 地址与文件布局

示例配置：

```text
主更新地址：https://cdn.example.com/patch/
备用更新地址：http://<服务器公网IP>:<HTTP端口>/
```

两个根地址下必须公开提供相同的相对文件：

```text
PList.Bin
APKVersion.bin.gz
Logs_8_22.txt.gz
其他由 PList.Bin 引用的文件名.gz
```

对象存储只开放匿名读取，不开放匿名写入。访问密钥只保存在服务器同步工具或管理员环境中，不得写入或分发到登录器。

## 生成器配置兼容

- `LauncherSet` 在现有“更新地址”下面增加“备用更新地址”输入框。
- 主地址继续保存为 `Config.Host`；备用地址新增独立配置项，供 `LauncherSet.ini` 保存和再次编辑。
- 生成登录器时，将两个地址编码进现有的更新地址字符串，例如：

```text
https://cdn.example.com/patch/|http://<服务器公网IP>:8000/
```

- 不增加生成登录器尾部数据的新字段，以避免改变现有字段顺序和尾部偏移结构。
- 新版登录器以 `|` 分隔地址；没有分隔符时按单地址处理，保证旧配置和只配置一个地址的生成方式继续可用。
- 保存前去除首尾空白，验证地址必须是绝对 `http` 或 `https` URI，并将根地址规范为以 `/` 结尾。

## 登录器下载流程

### 下载源解析

- 启动时解析嵌入的更新地址字符串，得到按顺序排列的主源和备用源。
- 忽略空地址和完全重复的地址；至少保留一个有效来源。
- HTTP 文件地址使用 URI 合并，不再使用文件系统路径拼接，避免产生反斜杠 URL。

### 获取补丁清单

1. 请求主源的 `PList.Bin`。
2. 网络失败、超时、HTTP 非成功状态、内容为空或清单解析失败时，请求备用源的 `PList.Bin`。
3. 第一个成功下载并完整解析清单的来源成为本次更新的当前来源。
4. 两个来源都失败时，显示“无法连接到更新服务”，附带主、备用来源的简短失败原因，并结束本次更新。

每个来源的清单请求连接超时为 10 秒，读取超时为 30 秒；超时后立即尝试下一来源。补丁文件请求同样使用 10 秒连接超时和 30 秒读写超时，但不限制完整文件的总下载时长。这些值固定在登录器内部，不暴露为玩家配置项。

### 下载补丁文件

1. 每个文件先从本次更新的当前来源下载。
2. 当前来源失败时，删除该文件的不完整临时下载，并从另一个来源重试一次。
3. 备用来源成功后，将其提升为本次更新后续文件的当前来源，避免每个文件重复等待故障线路。
4. 下载文件先写入临时位置，不能直接覆盖正式游戏文件。
5. 校验下载到的 `.gz` 长度是否等于清单中的 `CompressedLength`。
6. 解压到临时输出后，计算原文件 MD5，并与清单中的 `CheckSum` 比较。
7. 只有长度和 MD5 都通过，才替换正式文件并累计完成进度。

如果备用服务器与对象存储内容不同，主清单中的长度和 MD5 会阻止错误版本覆盖客户端文件。

### 完成与失败

- 只有全部所需文件下载、解压和校验成功后，才保存新的 `Version.bin`、删除本次临时目录并显示“完成”。
- 任意文件在两个来源都失败，或者两个来源提供的文件都校验不通过时，本次更新失败。
- 失败时保留原 `Version.bin`，不显示“完成”，不启动自更新替换程序。
- 临时文件可以在下次检查前清理，但不能把半下载或校验失败的内容当成正式文件。
- 修复模式与普通更新共用同一套双源和校验流程。

## 界面行为

登录器不增加线路按钮，只复用现有状态文本显示：

```text
正在从高速线路获取补丁信息
高速线路不可用，正在切换备用线路
正在从备用线路下载：<文件名>
文件校验失败：<文件名>
两个更新线路均不可用
```

不向玩家显示对象存储凭据、服务器目录或异常堆栈。

## 补丁发布流程

第一阶段不修改 `PatchManager`：

1. `PatchManager` 继续通过 FTP 将补丁发布到服务器的 `D:\FTP1\patch`。
2. 管理员使用对象存储厂商的官方同步工具，将该目录同步到对象存储的 `patch/` 前缀。
3. 先同步全部 `.gz` 补丁文件，确认成功后最后上传 `PList.Bin`。
4. 发布完成后分别验证主、备用两个地址的 `PList.Bin` 和至少一个本次新增 `.gz` 文件。

如果后续确实需要一键发布，再单独设计 `PatchManager` 对象存储上传功能；本次不引入厂商 SDK、云端访问密钥或新的发布按钮。

## 修改范围

允许修改：

- `LauncherSet/Config.cs`
- `LauncherSet/LMain.cs`
- `LauncherSet/LMain.Designer.cs`
- `LauncherWpf/MainWindow.xaml.cs`
- 必要时在 `LauncherWpf` 内增加一个只负责下载源解析和 URI 合并的小型类
- 针对双源解析、切换和完成条件的契约测试

禁止修改：

- `PList.Bin` 和 `PatchInformation` 的二进制格式
- `PatchManager` 的 FTP 上传流程
- 服务器、手游和游戏逻辑工程
- 登录器现有页面布局之外的无关控件和样式
- 正式发布目录中的可执行文件；验证构建必须输出到隔离目录

## 测试与验证

实现阶段先建立失败契约，再修改生产代码。至少覆盖：

1. 单个旧格式地址仍可下载清单和补丁。
2. 主、备用地址能从生成器写入并由生成登录器按原顺序读出。
3. 主源正常时不访问备用源。
4. 主源 `PList.Bin` 请求失败或内容无效时，自动使用备用清单。
5. 主源单个 `.gz` 失败时，从备用源下载并继续更新。
6. 切换备用源成功后，后续文件优先使用备用源。
7. 备用文件长度或解压后 MD5 不匹配时拒绝替换正式文件。
8. 两个来源都失败时不保存新 `Version.bin`，不显示“完成”。
9. 下载中断产生的临时文件不覆盖现有游戏文件。
10. 修复模式和登录器自身更新继续工作。
11. `LauncherSet` 和 `LauncherWpf` 在隔离输出目录完成 Release/AnyCPU 构建。

网络契约使用本地临时 HTTP 服务模拟成功、404、超时、中断和内容不一致，不连接正式补丁服务器或真实对象存储。真实双源访问作为部署后的独立验收。

## 验收标准

- 不增加玩家选择线路的操作。
- 对象存储正常时，登录器从主源完成更新。
- 主源不可用时，登录器能够自动从当前服务器完成同一补丁更新。
- 双源内容不一致或文件损坏时，不覆盖正式文件，不写入错误版本信息。
- 旧单地址生成配置继续可用。
- 补丁格式和现有 FTP 发布流程保持不变。
- 自动化契约和隔离构建通过；真实对象存储同步、外网下载速度和线上更新仍需单独运行验收。

## 非目标

- 普通网盘分享页、登录、提取码、Cookie 或验证码处理。
- 多线程分片下载、断点续传、线路测速或玩家手动选线。
- 修改补丁压缩格式或清单协议。
- 在本阶段把对象存储上传集成进 `PatchManager`。
