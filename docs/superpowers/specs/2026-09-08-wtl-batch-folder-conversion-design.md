# WTL 批量与文件夹转换修复设计

## 目标

修复 `ILIB v2.0-WEMADE` 素材中遮罩类型高位导致的错误遮罩读取，使 `Equip.wtl` 不再触发 `Ionic.Zlib.ZlibException`；同时提供明确的批量文件转换和文件夹转换入口。

## 范围与约束

- 只处理 WTL 到 Black-Dragon ZL 的转换路径。
- 文件夹转换只扫描所选文件夹当前层的 `*.wtl`，不递归子文件夹。
- 每个源目录的输出写入其 `ConvertedZL` 子目录，不覆盖源 WTL 或源目录中已有的 ZL。
- 单个文件失败不终止后续文件；结束后显示成功数、失败数和失败文件名。
- 转换顺序执行，优先保证错误归属、进度显示和 WinForms 控件访问正确。
- 不修改其他素材格式转换，不部署或覆盖当前使用中的编辑器。

## 实现设计

### V2 遮罩标志修复

在 `Graphics/WTL1to1ZL.cs` 读取 V2 帧头时，将遮罩类型字节的 `0x80` 高位作为标志清除，再依据剩余值判断遮罩是否存在。`0x80` 因而归一化为 `0`，既有的 `1/3/5` 纹理类型保持不变。

本次只修改实际被“官方 WTL 1:1 黑龙 ZL”菜单调用的 `WTL1to1ZL`，不顺带修改未参与该转换路径的 `WTLLibrary`。

### 输出路径

为 `WTL1to1ZL.ToMLibrary` 增加显式输出文件路径，使调用方能够把结果写入 `ConvertedZL`。保留现有入口兼容当前调用方式，但新批量流程始终传入隔离输出路径。

### 批量选择文件

保留现有 `OpenFileDialog.Multiselect = true`，将菜单文字改为明确的“批量选择 WTL 转换 ZL”。所选文件按顺序转换，各自输出到源文件所在目录的 `ConvertedZL`。

### 选择文件夹转换

在同一“转换素材”菜单下增加“选择文件夹转换 WTL 到 ZL”。使用 `FolderBrowserDialog` 选择目录，只获取当前层的 `*.wtl`，按文件名排序后复用同一批量转换函数。

### 错误处理

每个文件独立 `try/finally`，确保转换对象被释放。失败项记录源文件名和异常首层消息；全部处理完毕后一次性显示汇总。未找到 WTL 时提示并返回，不创建空输出。

## 验证标准

1. 回归测试在修复前用 `Equip.wtl` 稳定复现 `invalid stored block lengths`。
2. 修复后同一测试可读取全部 20,000 个索引，并能在隔离目录生成 ZL。
3. 生成文件以 `Black-Dragon Version` 开头，可由 `BlackDragonLibrary` 重新打开，索引数与源文件一致。
4. 用一个此前正常的 V2 WTL 做对照，确认原有无高位标志的转换不退化。
5. 批量测试包含至少两个文件，并验证输出均进入 `ConvertedZL`。
6. 人为加入一个无效 WTL，验证该文件失败后其他有效文件仍继续转换，汇总数量正确。
7. 构建成功；原始 WTL、当前 `D:\111\8.31素材编辑器\Z3素材编辑器.exe` 及非目标源码文件哈希保持不变。

## 产物边界

先生成独立测试版编辑器和 `ConvertedZL` 测试输出。是否替换现有编辑器由用户在验证结果后另行确认。
