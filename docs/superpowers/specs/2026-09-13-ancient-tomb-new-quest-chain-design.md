# 新建古墓任务链设计

## 目标

在不改变现有随机任务 172、173、174 的前提下，新建古墓三任务链，并让古墓石碑使用新任务的 `ExtraInfo` 字符完成二层验证。

## 任务流程

1. 405 号 `『盗墓贼』` 提供并完成 `尸体搜索`。
2. 完成前置任务后，接取 `盗墓者日记1`；在古墓1层击杀普通古墓士兵，100%获得并拾取 `盗墓者日记任务书1`，回盗墓贼处交任务。
3. 接取 `盗墓者日记2`；同样击杀古墓1层普通古墓士兵，获得并拾取 `盗墓者日记任务书2`，回盗墓贼处交任务。
4. 三个新任务完成后，石碑显示三个字符；正确输入进入二层，错误输入进入错误区域。

## 实现

- 新任务编号使用当前数据库最大任务编号之后的三个未占用编号；不复用 172/173/174。
- 新任务书使用当前数据库最大道具编号之后的两个未占用编号，作为原生 `GainItem` 任务掉落，不设置为 `QuestStarter`。
- `QuestTaskMonsterDetails` 只绑定古墓1层地图和普通古墓士兵，避免改变普通掉落表。
- `Server.ini` 的 `PenetraliumKeyA/B/C` 改为三个新任务编号；成功区和错误区配置保持不变。
- 完成任务脚本改用新任务编号，保留字符唯一性和 `ExtraInfo` 幂等逻辑。
- 盗墓贼脚本监听改为实际 NPC 编号 405。

## 边界

- 不改现有 172/173/174 数据。
- 不改客户端和服务器 C# 逻辑；已有石碑传送契约满足正确/错误分支。
- 不改 `Scripts888`，不复制到服务器，不重启服务。
- 新任务不设置额外奖励，避免引入未指定的奖励内容。

## 验证

- 契约测试确认配置、脚本和数据库三者绑定同一组新任务编号。
- 数据校验确认任务前置关系、任务书、古墓1层普通士兵掉落关联和客户端数据库记录一致。
- 两个目标 Python 脚本进行语法编译检查。
