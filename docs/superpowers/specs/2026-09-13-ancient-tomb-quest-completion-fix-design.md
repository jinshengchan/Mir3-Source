# 古墓三字符任务完成脚本修复设计

## 目标

修复服务器脚本中任务 172、173、174 完成后没有写入墓碑字符的问题，使古墓 1 层的三字符校验能够读取并在客户端显示正确字符。

## 已确认的现状

- `Server.ini` 将 `PenetraliumKeyA/B/C` 配置为 172、173、174。
- `完成任务.py` 中 `OnCompleteQuest`、字符生成逻辑和事件注册全部被注释，因此不会执行。
- `Player/事件触发/__init__.py` 当前没有导入 `完成任务.py`。
- `say()` 在目标脚本中没有定义。
- 客户端按 `ExtraInfo` 的字符串值查找字符编号，合法值为 `"1"` 到 `"24"`。
- 服务器在任务完成事件后同步 `UserQuest.ExtraInfo`；古墓入口再按 172、173、174 的顺序严格比较。

## 方案

只修改 `D:\Debug\4月18日更新\Server\Scripts` 下的两个脚本：

1. 在 `Player/事件触发/__init__.py` 加载 `完成任务.py`。
2. 在 `完成任务.py` 启用 `OnCompleteQuest`，仅处理 172、173、174。
3. 每个任务完成时，在 1 到 24 中生成一个与此前字符不同的编号，并以 `str(number)` 写入当前任务的 `ExtraInfo`。
4. 如果当前任务已有 `ExtraInfo`，保留原值，避免重复触发导致字符改变。
5. 如果前置任务字符缺失或不是合法编号，不生成后续字符，避免保存无法通过入口校验的数据。

## 顺序与数据流

```text
完成172 -> ExtraInfo="A"
完成173 -> ExtraInfo="B"，B != A
完成174 -> ExtraInfo="C"，C != A 且 C != B
古墓石碑 -> 客户端显示 A/B/C -> C.EnterAncientTomb -> 服务器严格校验顺序
```

## 范围边界

- 不修改 `Scripts888`。
- 不修改客户端、服务器 C# 源码、数据库或 `Server.ini`。
- 不复制到服务器、不重启服务端；部署和实机进入古墓属于后续人工验收。
- 不增加固定字符、玩家选择界面或额外奖励。

## 验证标准

- 两个脚本能被目标 Python 语法检查通过。
- `完成任务.py` 有且只有一个有效的 `OnCompleteQuest` 注册。
- 处理范围为 172、173、174，保存值为 1–24 的字符串，并保持三者不重复。
- 已存在的 `ExtraInfo` 不被覆盖。
- 静态检查确认没有残留的 `say()` 调用或仅被注释的处理逻辑。
- 实际服务器测试时，完成三个任务后打开古墓石碑，顶部三个字符应与下方选择结果一致；提交正确顺序进入等待厅，错误顺序进入错误地图。
