# 假人管理分栏与启动时序修复设计

## 问题与证据

- 在 1380×780 的运行时窗体中，`SplitContainer` 实际宽度为 1380，但左栏为 1113、右栏仅 263。原因是分隔位置在控件获得真实宽度前设置，随后被 MDI 布局按错误比例放大。
- `D:\Debug\4月18日更新\Server\Logs\Logs_9_16.txt` 显示假人配置第 8–207 行全部出现空引用，最终加载 0/15。配置文件各数据行符合当前三字段格式；失败发生在 `SMain_Load` 提前调用 `BotManager.Start` 时，此时数据库集合尚未初始化。

## 修复范围

1. `Server/Views/BotConfigView.cs`
   - 将分隔位置设置移动到 `SplitContainer` 已加入窗体并完成初始布局之后。
   - 左栏保持约 530px，右栏占用全部剩余宽度；两栏各自保留纵向滚动。
2. `Server/SMain.cs`
   - 删除 `SMain_Load` 中过早的自动启动。
   - 在服务端环境已启动、账号/角色/假人集合均已就绪后，只尝试一次自动启动。
3. `Server/BotManager.cs`
   - 在 `Start` 入口增加数据库就绪保护。未就绪时记录一条明确日志并返回，不逐行解析配置。
4. 回归契约
   - 布局契约验证分隔位置在控件加入窗体后设置，并通过运行时反射确认 1380px 宽度下右栏不少于 700px。
   - 启动契约验证 `SMain_Load` 不直接启动假人，自动启动具备数据库就绪条件，`BotManager.Start` 有入口保护。

## 不变项

- 不修改 `假人.txt`、数据库内容、客户端、部署目录或正式运行进程。
- 不改变现有假人功能、配置字段和 PVP 合法性保护。
- 不顺带重构管理面板或服务器启动架构。

## 验收标准

- 1380px 宽窗体中左栏约 530px，右栏可完整显示 505px 宽的配置组。
- 数据库未就绪时启动假人只产生一条明确日志，不出现逐行空引用。
- 数据库就绪后“启动时自动运行”仍按现有配置生效。
- 五组假人管理契约全部通过；ServerLibrary 与完整 Server 构建无错误。
- 新构建可创建标题为“Z3服务端”的响应窗口；不执行部署和正式启动。
