# 地图坐标实际地图绘制设计

## 目标

将“地图坐标编辑器”当前基于 `MiniMap.Zl` 整图缩放的背景，改为按照内置地图编辑器的规则读取 `.map` 单元格，并使用客户端 `Data\Map Data` 下的实际地图素材绘制。现有双地图对照、坐标选择、阻挡区域、对象标记、地图连接编辑和缩放功能保持不变。

## 范围

- 继续使用现有 `MapCoordinateForm`、`MapCoordinateCanvas` 和 `MapFileReader`。
- 支持当前已经能够打开的两种地图格式：韩版传奇 3 格式和 C# 自定义格式。
- 扩充现有单元格数据，保存内置地图编辑器绘制需要的中层、前层动画帧及动画间隔。
- 从当前设置中的 Client Data 推导 `Data\Map Data`，按 `Libraries.KROrder` 和 `Libraries.LibraryList` 解析地图文件编号到 ZL 文件。
- 不引入 SharpDX、DevExpress 或 ServerTool 项目依赖，不修改客户端和服务端运行逻辑。

## 绘制规则

绘制使用内置地图编辑器相同的基础坐标：每个地图单元格为 48×32 像素。

每一帧按以下顺序绘制当前可见范围：

1. 偶数坐标上的 Back 地砖层。
2. 尺寸为 48×32 或 96×64 的 Middle、Front 标准地砖层。
3. Middle 大型物件层，底部与所在单元格对齐。
4. Front 大型物件层，底部与所在单元格对齐。
5. 当前地图坐标工具的阻挡区域、地图对象、入口出口和选区覆盖层。
6. 放大到足够比例时显示坐标网格。

Middle 和 Front 动画按照地图文件中的帧数与间隔推进。素材索引、阻挡位掩码和前景索引掩码沿用内置地图编辑器规则。

## 资源管理与性能

- 地图库按需打开，只有可见单元格引用到的 ZL 才加载。
- 解码后的图片按“素材库路径 + 图片索引 + 图层类型”缓存，左右两张地图共享缓存。
- 画布使用虚拟滚动范围保存整张地图尺寸，实际控件保持视口大小，不创建数万像素宽高的 WinForms 控件。
- 画布只绘制可见区域；大型物件层按照内置地图编辑器规则额外读取视口下方最多 20 行，不预生成整张地图位图。
- 地图切换和窗体关闭时释放不再使用的图像与素材库句柄。
- 动画计时器只在窗体可见且当前画面含动画素材时刷新，避免空闲重绘。

## 缺失资源与回退

- 单个素材文件或图片索引缺失时跳过该图块，继续绘制其余图层。
- 实际地图素材完全不可用时，自动回退到现有 `MiniMap.Zl` 背景。
- 状态栏显示缺失素材库数量或回退原因，不弹出重复错误窗口。
- 不修改、复制、转换或覆盖 Client Data 中的任何素材。

## 缩放与交互

- “重置”以 1:1 实际像素显示 48×32 地图格。
- “放大”和“缩小”围绕当前视口中心改变比例，并保持滚动位置稳定。
- 实际地图图层使用最近邻缩放，保持像素清晰；文字、标记和选择边框仍使用正常 GDI+ 绘制。
- 鼠标坐标换算基于 48×32 单元格和当前缩放比例，不再依据 MiniMap 图片宽高。

## 验收标准

1. 同一张地图在地图坐标工具和内置地图编辑器中，Back、Middle、Front 的位置和遮挡顺序一致。
2. 1:1 与放大状态下素材保持像素清晰，不出现整图插值导致的模糊。
3. 左右两张地图可同时显示、滚动、缩放和选择坐标。
4. 入口、出口、NPC、卫士、阻挡区域及选区与实际地图格准确对齐。
5. 缺少部分地图素材时窗口保持响应；全部实际素材不可用时显示 MiniMap 回退画面和状态原因。
6. 连续切换普通地图与大型地图不会卡死，内存不会因旧地图图像持续增长。
7. LibraryEditor Debug x86 构建通过；现有地图连接数据读写行为不变。

## 验证方法

- 用一个当前正常显示的地图，与内置地图编辑器并排核对固定坐标处的三层素材。
- 用包含动画前景的地图核对帧推进与停止条件。
- 用缺少一个素材库的隔离副本验证部分缺失和 MiniMap 回退。
- 用大型地图反复切换和缩放，检查界面响应、异常和内存释放。
- 对已保存的地图连接执行读取、编辑、保存和重新加载回归检查。
